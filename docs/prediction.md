# Prediction Modeling & Anti-Leakage Framework

## Anti-Leakage Design

In financial machine learning, data leakage occurs when future information accidentally leaks into training features for date $T$.

Our feature engineering engine (`src/features/builder.py`) strictly enforces point-in-time calculation:

1. **Features ($X_T$)**: Calculated strictly using price and volume data up to and including date $T$.
2. **Targets ($y_T$)**: Forward targets (e.g. `future_return_5d`) are generated by shifting close prices backward:
   $$ y_T = \frac{\text{Close}_{T+5} - \text{Close}_T}{\text{Close}_T} $$
3. **Time-Series Splitting**: When training ML models (`MLPredictionModel`), data is split chronologically (e.g. first 80% dates for training, last 20% for testing). **Random temporal shuffling (e.g. standard K-Fold) is strictly prohibited.**

## Baseline Models

Initially implements Random Forest Classifier and Logistic Regression baselines using walk-forward evaluation metrics (Accuracy, Precision, Recall, F1, ROC-AUC).
